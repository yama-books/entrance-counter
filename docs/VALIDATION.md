# APP-026 初期実装の検証

架空の担当者名・メモ・人数だけを使用する。受付の実記録をテスト、GitHub、Actionsログへ入れない。

## 実行方法

Node.js 24で `npm ci`、`npm test`、`npm run check`。
ブラウザ試験は `npx playwright install --with-deps chromium webkit` 後に `npm run test:browser`。WebKitは `BROWSER=webkit npm run test:browser`（PowerShellでは `$env:BROWSER='webkit'` を設定）。
ローカル閲覧には任意の静的HTTPサーバーを使用する。file://では起動しない。

## 自動確認の範囲

- 入場10回・赤煉瓦3回の独立加算、連打、JSTの日付跨ぎ、5分/15分/30分/60分集計、担当者の確定時名。
- IndexedDB保存と再読込、担当変更、メモの安全なテキスト表示と保持、確認付き取消。
- 同一ブラウザの複数タブ同時保存、同一ID再保存、無効な取消のトランザクション中断、閉じたDBの保存拒否。
- 保存例外時に合計を増やさず、メモ入力を保持して再試行。実際の容量不足の再現ではなく例外注入による試験。
- CSV/JSONダウンロード、空のブラウザへのJSON復元、追加復元の重複防止、不正ファイル拒否。CSVの数式解釈対策。
- 1194×834、1024×768、768×1024、390×844で横方向のはみ出しなし、横置きで加算ボタンが画面内。モーション軽減設定。
- 接触（pointerdown）中に保存して数字が更新され、続くclickで二重計上しない。タッチ・Enter・Space各1回の加算、数字の上向きアニメーションとモーション軽減時の抑止。
- 記録一覧内で引継ぎ本文をテキスト表示して強調。最新メモはカウントが増えても上部に表示。5分集計・最新メモ表示中も横置きで「シフト表」までの全メニューが画面内。
- シフト画像の保存・再読込・差替。不正画像・保存例外時に元画像を保持。画像保存はイベント件数を変えない。試験には既存の公開PNGのみを使用。

## 保存仕様・範囲

集計日はJSTの0時区切り、時刻は端末時計。記録IDはUUID。担当未入力時は「未設定」として受付できる。担当変更後も過去記録の担当者名を維持する。取消は対象IDへの追記で、修正後の入力は新たなカウントとして記録する。

IndexedDBの単一レコードをreadwriteトランザクションで更新する。表示は保存成功後に変更する。同一端末のタブ間競合はこのトランザクションで直列化する。1タップは1件なので、連続タップを一律に捨てる処理はしない。通信による同期はない。

タップ時に全画面を同期的に描き直さず、画面更新をフレーム単位でまとめる。閉じたダイアログの内容は開いた時に描画する。日時フォーマッタは再利用する。押下フィードバックは即時、数字の増加表示は保存成功後。

シフト表の画像は同じIndexedDBストアの別キー `shift-image` にBlobで保存する。PNG/JPEG/WebP/GIF、10MB以下・4,000万画素以下。画像読込と保存が成功した後に差し替える。受付記録のデータ形式は変更せず、既存の記録・バックアップをそのまま利用する。画像はJSON/CSVに含まれないので元画像を別に保管する。

JSON復元は既存記録を消さず追加し、同一ID・同一内容は重複しない。同じIDで内容が異なる場合は拒否。古い担当変更を復元しても最新担当を維持する。上限は200,000イベント、復元ファイル30MB。単一レコード方式のため、大量記録の長期運用性能は未検証。定期的なJSON保存を推奨する。

PagesにはHTML/CSS/JSと切り出しPNGだけを配信する。外部API、解析、認証、クラウド保存、Service Workerは使用しない。再度アプリを開く際のオフライン起動は保証しない。

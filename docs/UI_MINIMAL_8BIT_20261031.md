## 1. 優先度：使いやすさ
1. iPad Safari横置き。主要なカウント操作を大きく、画面全体が事務端末として自然に見えること。
2. 背景は白〜アイボリー、余白は広め。枠線は細く明瞭。色面は入場（くすみ若草）と赤煉瓦（くすみ煉瓦色）の加算ボタンなど必要な箇所だけ。
3. 光・花びら・大量の装飾・グラデーション・過度な角丸・大きな影は避ける。8bit感は画像・数字の角ばり・ボタンの2〜3pxの沈みで表現。
4. ネコチャン＋本と八重桜はヘッダー端の**小さなワンポイント**。イラストが受付業務の主役にならないこと。
5. 日本語の読みやすさを最優先し、ピクセルフォントを全面適用しない。

## 3. アイコン整理
- 八重桜（旧 ART-01）とネコ＋本（旧 ART-02）は再利用可。ただし表示を小さく抑える。
- 赤煉瓦（旧 ART-04）は再利用可。
- 入場者三人アイコンは**新ピクトグラムへの更新必須**。
- 集計、単独人物、メモは、確定モックの**フラットな線と少ない色数**にそろえる。既存PNGの流用または小さな独立透過PNG作成は品質を比較して決める。
- 画像素材は透過PNGを優先。**画面全体を画像として貼らず**、数値・ボタン・グラフ・表・タブはHTML/CSS/JSで構成する。
- テキスト・矢印・罫線等のために不要な画像を増やさない。

## 4. 既存機能を維持
- 1押下1イベント・タイムスタンプ・担当紐付け・訂正履歴・ローカル保存・CSV/JSON入出力。
- シフト表の画像登録・閲覧、配色5案、引継ぎメモ。
- 「山本を呼ぶ」GASメール呼出、日付ごとの予定、担当者名必須の入力、パスコード設定。**この機能を削除・初期化しない**。デザイン内にボタンが描かれていない場合は、既存の機能をヘッダーの補助ボタンや設定内に確保する。
- iPad Safari横置きに加え、縦画面・拡大時も主操作が失われないこと。
- スクリーンショットにないシフト表・呼出・取消・配色・データ管理は既存UIを縮退配置して機能を維持する。
- Public GitHubへ実際の担当者情報、受付ログ、引継ぎ本文、認証情報を掲載しない。

## 5. 実装／検収の区切り
1. **画像参照の保存・読戻し（別工程）**：画像ファイルのSHA・寸法を記録。
2. **UI試作**：画像とCSSで画面構造を再現。既存コードとの変更差分を限定。
3. **機能回帰**：入場／赤煉瓦計上・取消・時刻集計・担当・引継ぎ・シフト表・GAS・配色・データ出力を確認。
4. **公開**：PR/CI/main統合/Pagesデプロイをそれぞれ別の根拠で判定。
5. **実機**：iPad横置きSafariの表示・タップ・モーダル・データ保持を検収。
